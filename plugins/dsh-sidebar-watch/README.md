# 自选盯盘（dsh-sidebar-watch）

顶栏常驻一个**盯盘入口**：收起态是一条轮播（逐条滚动候选的名称 / 现价 / 涨跌幅），
点开是完整清单。盯盘要的是「一眼扫到」，不长期占侧栏版面。

## 用起来是什么样

1. **加候选**：在自选股表格的「操作」列点「盯盘」，这只票就进候选池；
2. **设阈值**：候选行右侧的铃铛点开阈值编辑器 —— 价格（涨到 / 跌到）或涨跌幅
   （涨幅达到 / 跌幅达到）二选一，数值为正、方向由按钮表达；
3. **到价提醒**：阈值到达时右下角弹浮窗，点浮窗直接看这只票；
   **同一只票只占一格**（反复触发是替换而不是刷屏），触发过一次后要等价格
   回到阈值内侧并越过回差才重新武装（防抖动刷屏）；
4. **跳详情**：点候选行跳个股详情整页，左侧来源列表 = 全部盯盘候选，可一键切换同批股票。

监控范围是**候选池 ∩ 当前自选股**：把票从自选股移出，该行与它的告警一起停下，
但候选记录与阈值仍保留 —— 重新加回自选股即自动续上。

## 为什么「你没在看的时候也在盯」

盯盘引擎（取报价 → 判阈值 → 弹提醒）跑在**插件层**，不在面板组件里：
顶栏下拉一收起，宿主就会把面板组件整个卸载，如果引擎挂在组件上，
告警就会随下拉一起停摆 —— 那正好是盯盘最没用的时候。

轮询用的是宿主 `app:polling`（交易窗口 / 失败退避 / 页面可见性四份策略只有一份实现），
全插件只有这一处报价请求。

## 数据存放在哪

- 候选与阈值落在本插件独立表 `plugin_dsh_sidebar_watch_watch_candidates`
  （宿主 `ctx.db`，Tauri 端 SQLite / 浏览器端本地仿真），**插件永不直接写 SQL**；
- 卸载插件时宿主会询问是否一并删表；**插件 id 一个字都不能改**
  （名字里的 sidebar 是历史遗留，改 id = 换一批新表，候选与阈值全部失联）。

## 对外提供什么

服务 `watch:repo`：其他插件 `ctx.consume('watch:repo')` 可读写同一份候选池。

## 依赖的宿主服务

`app:ui`（弹窗 / 骨架屏 / 按钮 / 输入框 / 图标）、`app:format`（价格 / 百分比 /
涨跌色 / 符号归一化 / 按符号查报价）、`app:quotes`（批量取现价）、`app:polling`
（轮询调度器）、`app:stock-open`（跳详情侧栏 / 详情整页）、`app:watchlist`（候选 ∩ 自选股）、
`app:notify`（阈值浮窗）、`app:navigate`（打开自选股页）、`panel:close`（点完收起下拉）。
