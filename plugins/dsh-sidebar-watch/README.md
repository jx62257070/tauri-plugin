# 自选盯盘（dsh-sidebar-watch）

安装包从 [GitHub Release](https://github.com/jx62257070/tauri-plugin/releases) 下载，文件名形如 `dsh-sidebar-watch-<版本>.zip`（版本以 Release 页面为准）。

一句话：顶栏常驻一个**盯盘入口** —— 收起态是一条轮播（逐条滚动候选的名称 / 现价 / 涨跌幅），点开是完整清单。盯盘要的是「一眼扫到」，不长期占侧栏版面。

2.0.0 起，原「任务栏盯盘小组件」已并入本插件：同一份候选、同一份报价引擎，另可在 Windows 任务栏上方常驻一个**置顶迷你条**（默认开启，在插件设置里开关）。

## 功能特性

**顶栏盯盘主体**

- **顶栏常驻入口**：挂在应用顶栏右侧，收起态轮播候选，点开是完整清单。
- **逐只加入候选**：在自选股表格的「操作」列点「盯盘」，这只票就进候选池；再点一次即移出。
- **到价 / 涨跌幅提醒**：候选行右侧的铃铛点开阈值编辑器，价格（涨到 / 跌到）或涨跌幅（涨幅达到 / 跌幅达到）二选一，数值为正、方向由按钮表达；到价时右下角弹浮窗，点浮窗直接看这只票。
- **防抖动设计**：同一只票只占一格（反复触发是替换而不是刷屏），触发过一次后要等价格回到阈值内侧并越过**回差**才重新武装。
- **候选池可被复用**：提供 `watch:repo` / `watch:monitor` 服务，其他插件可读写同一份候选池与报价快照。

**任务栏小组件（2.0.0 并入，可选）**

- **迷你条轮播**：任务栏上方常驻一个置顶迷你条，轮播同一批盯盘候选的名称 / 现价 / 涨跌幅，阈值触发带提示点。
- **气泡三视图**：单击迷你条展开气泡看全部候选；气泡头部图标在「自选盯盘 → 板块热力 → 大盘走势（市场总览同款 10 指数：A 股 4 + 海外 6）」间循环切换，均仅展示无交互。
- **摸鱼显隐**：可设「鼠标离开自动隐藏」，移到屏幕右下角热区即唤回；拖动位置会被记住。
- **主题跟随**：明暗 / 主题色 / 涨跌配色实时跟随主窗口。

## 安装

前置：已安装 **[WHF 股票看板](https://github.com/WHF293/whf-stock-board)**。

1. 打开应用，进入「插件工坊」（应用内的插件管理入口）；
2. 选择「导入插件」，选中刚下载的 zip 安装包；
3. 导入后启用，顶栏会出现盯盘入口。

卸载：在「插件工坊」里对该插件点卸载，应用会询问是否一并删除本地数据表。

## 设置

插件设置里有「任务栏小组件」一栏（插件工坊 → 本插件 → 设置），三个字段改动即时生效：

| 设置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 小浮窗 | 常驻显示 / 智能开启（仅交易日盘中）/ 关闭 | **常驻显示（默认开启）** | 迷你条出不出来；「智能开启」只在交易日 9:30-15:00 显示 |
| 显示模式 | 一直显示 / 鼠标离开自动隐藏 | 一直显示 | 条出现后的行为，与电源正交 |
| 自动隐藏延时（秒） | 1 ~ 30 | 3 | 仅在「鼠标离开自动隐藏」模式下生效 |

两点说明：

- 拖动迷你条后的落点也记在这份设置里（宿主表单没有坐标控件，由插件自行回写）；点「恢复此插件默认设置」会连落点一起清掉，条回到工作区右下角停靠。
- 不需要小组件就在上面把「小浮窗」设成「关闭」—— 关掉后不建任何窗口，顶栏盯盘主体完全不受影响。

## 从旧包升级（重要）

如果你之前装过独立包 **`dsh-watch-widget`（任务栏盯盘小组件）**：请到插件工坊**卸载它**。

- 合并后本插件已包含它的全部功能，旧包不会再收到更新；
- 旧包留在系统里会和本插件抢同一个窗口（快照被推两份、条自己忽隐忽现）。本插件检测到它仍处于启用状态时会主动让位并弹一条提醒，但它一直挂着，小组件就一直归它管；
- 卸载旧包**不会影响**你的盯盘候选与阈值 —— 它们本来就在本插件的数据表里。

## 快速上手

1. 打开自选股页，在「操作」列点「盯盘」，这只票就进候选池；
2. 点候选行右侧的铃铛设置阈值：先选类型（价格 / 涨跌幅），再选方向（涨到 / 跌到），填数值；数值填正数，方向由按钮表达；
3. 阈值到达时右下角弹浮窗，点浮窗直接看这只票；
4. 点候选行跳个股详情整页，左侧来源列表 = 全部盯盘候选，可一键切换同批股票；
5. 第一次打开时清单为空 —— 空态提示会告诉你候选从哪里来；
6. 想要任务栏迷你条：默认就是开着的（Windows 桌面端，且应用侧已内置小组件渲染端）。

## 依赖

主体需要宿主提供：`app:ui` / `app:format` / `app:quotes` / `app:polling` / `app:stock-open` / `app:watchlist` / `app:navigate` / `panel:close`；`app:notify` 缺失时阈值提醒只进日志。

小组件部分额外需要：`app:theme`（主题同步）与 `app:market-status`（智能开启的盘中判定）；`app:market` 为**可选**（缺失时热力 / 大盘视图空态降级）。这些能力缺任何一个，**只有小组件缺席**，顶栏盯盘主体照常工作，插件不会失败、不会回滚。

## 数据与隐私

- **数据来源**：报价走 WHF 股票看板提供的行情服务（`app:quotes`），轮询统一由应用的轮询调度器（`app:polling`）驱动，全插件只有这一处报价请求 —— 小组件复用同一份快照，不产生第二份行情请求。
- **联网时机**：仅在应用设定的交易窗口内、由应用的轮询调度器按固定间隔取报价；候选池新增未取过价的标的时会先补拉一轮。气泡展开且切到「板块热力 / 大盘走势」视图时，额外以 30 秒间隔经宿主 `app:market` 取板块与指数快照，收起 / 切走即停。
- **本地存储**：候选与阈值落在插件的独立本地数据表 `plugin_dsh_sidebar_watch_watch_candidates`（桌面端 SQLite / 浏览器端本地仿真），插件永不直接写 SQL；阈值规则与「已触发」状态同表落地，重启后仍保留。小组件的三个设置项与拖动落点存在插件自己的设置存储里。
- **卸载影响**：卸载时应用会询问是否一并删除数据表；**插件 id 一个字都不能改** —— 改了就等于换了一批新表，候选与阈值全部失联。

## 与其他插件的互操作

| 类型 | 名称 | 语义 |
| --- | --- | --- |
| 服务 | `watch:repo` | 其他插件 `ctx.consume('watch:repo')` 即可读写同一份候选池 |
| 服务 | `watch:monitor` | 1.4.0 起：盯盘引擎只读句柄，第三方插件读同一份报价快照，不产生第二份轮询 |

## 已知限制

- **监控范围**：候选池 ∩ 当前自选股。把票从自选股移出，该行与它的告警一起停下，但候选记录与阈值仍保留 —— 重新加回自选股即自动续上。
- **阈值二选一**：一只票同一时刻只能有一种阈值类型（价格或涨跌幅），不能两者并存。
- **提醒防抖动**：同类型提醒「只占一格」，触发后需价格越过回差才重新武装，因此不会对每一次越界都弹提醒。
- **小组件仅 Windows 桌面端**（Tauri）。浏览器端静默跳过，不建任何窗口。
- **小组件需要应用侧已内置渲染端**：迷你条窗口加载的是应用自带的 `watch-widget.html` 入口。应用版本还没带这个入口时，开了开关也只会浮出一块空白条 —— 关掉开关即可，不影响主体。
- **插件 id 的历史遗留**：入口已从侧栏搬到顶栏，但 id 仍为 `dsh-sidebar-watch`（名字里的 sidebar 已过时）。此为**故意不改** —— id 是数据表名与存储命名空间的一部分，改 id 等于让已积累的候选与阈值一夜清空。

## 设计说明

**为什么「没在看的时候也在盯」？** 盯盘引擎（取报价 → 判阈值 → 弹提醒）跑在**插件层**，不在面板组件里：顶栏下拉一收起，应用会把面板组件整个卸载，如果引擎挂在组件上，告警就会随下拉一起停摆 —— 而那正好是盯盘最没用的时候。引擎生命周期挂在插件上，卸载插件时才停轮询并清掉自己弹过的浮窗。

**为什么轮询不自己实现？** 轮询用的是应用的轮询调度器（交易窗口 / 失败退避 / 页面可见性等多份策略只有一份实现），全插件只有这一处报价请求，避免重复取数触碰上游频率红线。

**为什么小组件合并进来而不是继续做独立包？** 它俩本来就共用同一份盯盘数据源，独立包时期是靠插件间服务注入（甚至直接跨插件 import 源码）勉强拼起来的 —— 插件包是运行时动态装载的一段代码，跨插件源码 import 破坏隔离。合并后一份清单、一张候选表、一个引擎实例、一次安装、一次更新。

**为什么小组件失败绝不影响主体？** `apply` 抛错会让内核回滚本插件的全部贡献点（顶栏盯盘一起消失）。小组件被定位成**可选子系统**：能力缺失 / 非桌面端 / 用户关掉，都只是它缺席；挂载调用也包在 `try/catch` 里，任何意外只进日志。
